# Git 日常：状态、提交、历史、忽略

Git 的三个区：

| 区 | 说明 | 怎么进去 |
|---|---|---|
| 工作区 | 正在改的文件 | 直接编辑 |
| 暂存区 | 下一次提交要放进去的内容 | `git add` |
| 仓库 | 已经存好的版本 | `git commit` |

`git status` 里的两种状态：

| 状态 | 意思 |
|---|---|
| 未跟踪的文件 | Git 从没管过这个文件 |
| 修改 / 尚未暂存 | Git 管着它，但改了还没 add |

---

### `git config --global user.name "名字"` / `user.email "邮箱"`

- 作用：设置提交时署名；`--global` 对这台机器的所有仓库生效
- 说法：配置用户名邮箱；第一次用 Git；提交署名
- 分类：Git 日常
- 项目：练习：在 my-templates 时配过一次，之后豆瓣、Steam 都不用再配

### `git init`

- 作用：把当前目录变成 Git 仓库，生成 `.git`
- 说法：新建仓库；开始用 Git 管理；初始化
- 分类：Git 日常
- 项目：练习：my-templates；豆瓣：项目做了一段时间后才 init

### `git status`

- 作用：看哪些文件改了、哪些已暂存、哪些没被跟踪
- 说法：看改了哪些文件；当前状态；有没有没提交的
- 分类：Git 日常
- 项目：全程；加完 `.gitignore` 后用它确认 `venv/`、`logs/` 不见了
- 坑：add 之后、commit 之前再看一次，确认没有 `.env` 这类不该提交的文件；推上 GitHub 后就很难撤回

### `git add 文件`

- 作用：把改动放进暂存区
- 说法：加入暂存；准备提交；把文件交给 Git
- 分类：Git 日常
- 项目：全程；逐个写文件名，比 `git add .` 更不容易把不该提交的东西带进去

### `git commit -m "说明"`

- 作用：把暂存区存成一个版本，附上说明
- 说法：提交；存个版本；保存进度
- 分类：Git 日常
- 项目：全程；说明写清楚“这一版做了什么”
- 坑：第一个提交最好是能跑的版本；先 build、跑通再提交

### `git log --oneline`

- 作用：一行一个提交，看历史
- 说法：看提交历史；提交了几次；最近改了什么
- 分类：Git 日常
- 项目：全程；`git log --oneline | head -15` 只看最近 15 个

### `git diff`

- 作用：看工作区相对上一次提交改了什么；`-` 是删掉的行，`+` 是加上的行
- 说法：改了哪些地方；对比修改；看改动内容
- 分类：Git 日常
- 项目：豆瓣：确认 Dockerfile 到底改没改；Steam：提交前检查有没有误改
- 坑：Git 逐行比较文字，改一行会显示成删一行加一行；`@@ -51,8 +51,9 @@` 是旧文件从 51 行起 8 行，变成新文件从 51 行起 9 行

### `.gitignore`

- 作用：列出不进 Git 的文件和目录
- 说法：哪些文件不提交；忽略文件；不要上传
- 分类：Git 日常
- 项目：Steam：`venv/`、`data/`、`logs/`、`backups/`；豆瓣：`.env`、测试脚本、`venv/`、`analysis/output/`、`fonts/`
- 坑：原则是代码进 Git，数据、日志、密码、环境不进；建 GitHub 仓库时可以选 Python 模板，但数据库文件不在模板里，要自己加

### 文件模式 `100644` / `100755`

- 作用：commit 输出里的 `create mode`，`100755` 表示可执行，`100644` 表示不可执行
- 说法：Git 记不记权限；脚本拉下来能不能直接跑
- 分类：Git 日常
- 项目：Steam、豆瓣：`chmod +x` 过的脚本是 `100755`，clone 下来自带执行权限

### 在容器里敲 `git`

- 作用：开发容器 `python:3.12-slim` 里没有装 git
- 说法：git command not found；容器里提交不了
- 分类：Git 日常
- 项目：Steam：报 `command not found`，`exit` 回宿主机再提交
- 坑：先看提示符判断自己在宿主机还是容器里
